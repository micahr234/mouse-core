# Repository instructions

## Review before publishing

- Authorization to implement or fix something is NOT authorization to publish it.
- Complete implementation and relevant checks locally, then present the changes
  for user review. Do not push to GitHub, merge, release, or otherwise publish
  until the user has reviewed the changes and explicitly approved publishing.
- This applies to all repositories, including shared packages and dependencies.
  Leave changes local while awaiting review; do not automatically publish to
  satisfy a dependency or complete a task.
- Inspect the working tree and include only intended changes in any commit.
  Preserve unrelated work and never force-push.
